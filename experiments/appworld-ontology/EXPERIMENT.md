# OWB01: visible ontology construction in AppWorld

Protocol version 1, 2026-10-20. This is a supporting demonstrator, not a sixth final product or a reproduction of OaK's published scores.

## Development amendments, retained separately

This is a development demonstration, not a sealed measurement protocol. Original construction rejections remain in the append-only ledger. Version 1.1 allowed up to five pre-action construction rounds with exact validator feedback. The model continued violating the allowed interface, and that construction policy was rejected without an AppWorld task attempt.

Version 2 changed the construction policy to model-selected pure operator expressions plus mechanical Python compilation. Its constructor saw the official task and available app descriptions, rather than the full selected API documentation used in version 1. These are different designs and are not a controlled comparison. Version 2.1 added mechanical JSON literal translation and an `onto_` namespace. The first original live expression plan was reused, with a `cached-live` reuse event. Later plans were not selected for favorable results. This reuse is not new model-quality evidence.

The one native agent attempt used that compiled first plan. Construction is frozen during the attempt. The completed task failed the official evaluator and is not repeated. A post-task feedback proposal is retained but not activated. The reviewer originally received full official training assertion traces, including expected values; the actor and initial constructor did not. This is training-derived review, not held-out evidence. Future feedback prompts omit assertion traces and expected values.

The development runtime manifest was captured after this demonstration. Source revisions during development mean this run is not a frozen performance comparison. Future runs capture the manifest before construction. Model-call metadata and exact delivered messages remain available individually.

Historical function-use counts represent retained wrapper stdout only. AppWorld suppressed stdout from an execution that later failed, so zero retained outputs cannot establish zero function use. A separate native wrapper ledger now addresses this instrumentation gap; its mechanics test is not model evidence. Historical counts are not rewritten.

## Question and contract

Can a user inspect a real model's domain definitions, fact extraction, selected concepts, generated functions, native AppWorld actions, official outcome, and feedback without confusing model suggestions with validated evidence?

The visible vertical slice uses official train task `22cc237_1`: reconstruct individual dinner shares from a note, match existing Venmo payments, and request only outstanding shares. Its task instruction is the success contract; the unchanged official AppWorld evaluator grades the final state. The model must select every application call. No reference solutions, private test data, expected answers, or sibling trajectories enter actor or constructor prompts.

## Bounded procedure

1. Preflight the configured live Vertex model. Stop live work on provider unavailability; never substitute responses.
2. Construct a candidate domain schema and pure data functions from the task instruction and public API documentation.
3. Validate wire contracts, references, and generated-code syntax/capability restrictions. OWL/HermiT is a distinct unavailable check until a Java runtime and actual reasoner are installed. Structural checks never stand in for it.
4. Run the official SimplifiedReActCodeAgent with the candidate definitions. All new AppWorld observations produce visible source-linked fact extraction and concept selection. Generated pure functions are installed into the native execution environment; actual use, zero use, arguments, and outputs remain visible.
5. Grade the saved native world in a fresh process, reconcile it with the executed world's canonical state, and retain the official outcome.
6. Ask the real model for a source-linked repair proposal, or an explicit no-change conclusion. A proposal does not activate a version or establish improved behavior.

This first slice is a train demonstration. It is not a held-out quality comparison. The UI must say so and must show pending/unrun stages. No conclusive task attempt may be selectively repeated. A changed candidate has a new version and identity.

## Later comparison, not yet evidence

Hold the actor, model/settings, external capabilities, task worlds, context entitlement, action policies, and official grader fixed. Report all planned, missing, excluded, and inconclusive counts. This comparison concerns the schema-plus-functions package, not ontology alone.

## Visibility and limits

Records include request identity, input provenance, versions, selected definitions, observed facts and uncertainty, generated code, calls, arguments, observations, state snapshots, official checks, call identity/model/prompt metadata, token usage and separate model/tool/grading times. No hidden chain-of-thought is requested or stored. Human guidance is a versioned proposal with a target and scope; it cannot silently change the task contract or active version. Captured history is evidence replay when viewed later, not a fresh live call.

A generous operational watchdog can stop a hung task but cannot turn it into a behavioral failure. Provider output truncation is inconclusive. Cost in dollars is unknown unless independently priced; token counts are reported. No claim of improvement is available from this demonstration alone.
