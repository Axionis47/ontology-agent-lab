# AppWorld Ontology Workbench

A local, visible training demonstration of ontology construction, fact extraction, context selection, generated functions, native AppWorld execution and independent task evaluation. This is a supporting investigation, not a sixth final product or an OaK reproduction.

Open `evidence.html` in a browser to explore the recorded v1/v2/v3/v3.1 metadata. Protected task detail is available through the encrypted sanitized bundle without a server or model calls. It is a read-only export of actual local records. Regenerate it with `python export.py` using the runtime below.

## Completed v3 enforcement loop

The final v3.1 treatment passed all four official AppWorld checks on train task `22cc237_1`, using real Vertex `gemini-2.5-flash` decisions and the unchanged official evaluator. Saved canonical state matched the executed world. The model invoked all three frozen ontology functions and committed exactly three native payment requests.

| Observed result | V2 | V3 | V3.1 |
| --- | --- | --- | --- |
| Official task success | false | false | true |
| Official checks passed | 3 / 4 | 1 / 4 | 4 / 4 |
| Generated function executions | 0 | 1 | 3 |
| Gate-committed requests | no gate | 0 | 3 |
| Model-action gate denials | no gate | 7 | 5 |
| Injected software denial probes | not run | 1 | 1 |
| Agent actions | 22 | 38 | 32 |

V2's four unresolved obligations were advisory. V3 makes native evidence reconciliation a prerequisite to effects. Software checks note-row coverage, identity joins, complete paginated received-payment history, event day and label, and amounts. The actor must execute `onto_reconcile`, `onto_outstanding_shares`, and `onto_request_plan` in order. Each executes the frozen, live-generated function and returns a host-owned receipt. Independent checks reject incorrect outputs. Only an exact, fresh plan receipt can authorize native requests. Raw writes, modified plans, duplicate commits and premature successful completion are denied.

Two failures remain visible. The first v3 attempt encountered a controller date-format defect; its official 1/4 result remains recorded, with a separate inconclusive/excluded classification. After that supporting fix, `run-dinner-v3-002` was a conclusive failure: it executed reconciliation but repeatedly passed a receipt envelope to an ID-only method. No requests were sent. That failure was not rerolled.

The separately declared v3.1 treatment, `run-dinner-v3p1-001`, accepts either the exact issued envelope or its ID, with matching instructions. It reuses the identical frozen ontology and generated code, with no constructor resampling. Altered receipts and raw rows remain invalid. It passed. The comparison has four version cells, six native attempts, four conclusive outcomes, two excluded inconclusive attempts and zero missing outcomes. All selected versions began from the same canonical state.

Open **Changes & results** for scores, all attempts and selectable adjacent diffs. **Inspect v3** retains the failure; **Inspect v3.1** opens the passing run. **Enforcement** shows the native evidence checks, actual function counts, receipts, denied attempts, exact native effects and independent event-order audit. **Generated functions** shows the frozen code and actual calls. **Decision context** exposes the exact context and full actor instructions at each step. Earlier context obligations remain historical snapshots; per-stage receipts in Enforcement are the execution evidence.

This demonstrates one bounded enforcement workflow succeeding on a previously seen training task. It does not isolate ontology effectiveness. Domain coverage assumptions, richer tools, context, software verification, development order and model variance matter. There is no held-out success rate, formal OWL proof, security sandbox guarantee, latency advantage or dollar-cost conclusion. The next quality experiment needs frozen treatments and disjoint cases. The conditional choice here is to retain evidence and function prerequisites before payment effects, with exact receipts that the actor can reliably pass.

## Completed v2 loop (historical)

The user requested revision and a new native AppWorld test after v1 failed. The live model generated a changed assistance package, which passed structural and independent unknown-status function checks and was activated as v2. The original v1 records were preserved.

**Partial improvement, not successful completion.** V2 added a Payment type and has_paid relationship, changed required boolean paid to optional string payment_status, added email lookup, and generated an outstanding-share function that excludes missing/paid statuses. Its context carries per-property citations and unresolved obligations, with live grounding review. These changes were frozen before execution. The treatment is the whole assistance package, not ontology alone.

V2 retrieved the payment-request API specification and used user_email correctly. It sent seven requests, including people who had already paid, so it failed the outstanding-share check. Immediately before this effect, all four tracked obligations, including payment reconciliation, remained unresolved. The warnings were advisory and did not enforce a precondition. The actor made no direct generated-function calls, and the native wrapper ledger captured zero. This attempt establishes no benefit from the generated function code.

The extra evidence checks rejected 11 context responses, including missing property citations, unsupported completion claims and transaction-ID type mismatch. No property claims were withheld by the grounding reviewer. That zero does not establish truth: many proposals were rejected before semantic review. Whole-response rejection still discarded useful partial information. See the source-linked engineering review in the UI.

V2 attempt run-dinner-v2-001 stopped after 22 actions on malformed extraction JSON, before grading. It is preserved as inconclusive/excluded. After a supporting parser-error guard was added, run-dinner-v2-002 resumed the cell from a fresh state with the EXACT same frozen package, no constructor resampling. There are two planned version cells, three native attempts, two conclusive outcomes, one excluded inconclusive attempt and zero missing outcomes. Both conclusive worlds started from the same canonical input state and were independently reconciled with saved grading state. No conclusive failure was rerun.

Live-dashboard guidance remains a recorded proposal; arbitrary future guidance is not automatically activated. Post-v2 model feedback proposes a later revision but does not activate v3.

This is a sequential, feedback-informed demonstration on a seen training task. V1 had development code changes and a late manifest; v2 added grounding and fixed function-call capture, then required a context wire-error handling fix. Task familiarity, order, extra calls/context, model variance, host load, cold starts, instrumentation and judge errors confound causal attribution. More passed checks alone does not show fewer harmful actions, a latency benefit, lower cost, or general ontology effectiveness. OWL/HermiT remains unavailable. The conditional engineering choice is to enforce evidence and obligation preconditions before payment effects, then evaluate that new design on preregistered disjoint cases. It is not implemented as a hidden change to v2.

## V1 history

The real Vertex model generated the domain definitions and function proposals. No model outputs were substituted. Two construction policies were developed, and all rejection records remain visible. They are not a controlled comparison:

| Policy | Observed result |
| --- | --- |
| Python function generation | Five construction rounds violated the allowed function interface. No AppWorld task attempt. |
| Operator expression composition | The first live expression plan was mechanically compiled after JSON-literal and namespace fixes. One native agent attempt, official failure. |

Native train task `22cc237_1` asks the agent to find dinner shares in SimpleNote, reconcile existing Venmo payments and request outstanding shares. The one task attempt took 13 agent steps. AppWorld reported 1 passed and 3 failed checks, with overall `success=false`. A fresh grading process read saved canonical state that matched the executed world. The failed attempt has not been rerun.

The model produced a flat `Coworker` schema with no typed relationships. It required `paid` before transaction evidence existed. At decision 7, extraction omitted this unknown field and was rejected; the unpaid function received an empty graph. At decision 8, extraction instead supplied unsupported `paid=false` values. Quote matching and field validation did not catch that semantic error. At action 12, the agent supplied `recipient_username` to an API requiring `user_email`, then terminated with failure. It had not reconciled payments or resolved identities. Its original model feedback proposed an email property and function but missed earlier problems. The richer v2 package and its observed partial improvement are described above; the original proposal was not directly activated.

There were 39 completed live model requests across preflight, failed construction rounds, extraction, actions and feedback. The compiler reuse of the original expression plan is separately identified as `cached-live`; mechanical checks are `not-a-model`. This is a development demonstration, with source revisions and a late runtime manifest. It supports inspection and debugging, not model-quality or performance conclusions.

## What this establishes, and the next experiment

It establishes a complete visible revision loop and a case-specific increase in passed checks. V3.1 completed this case after the preserved earlier failures. There is no no-ontology control, held-out evaluation, formal OWL validation or ontology-quality score.

Before comparing quality: represent unknown payment status explicitly, retain partial observations without fabricating completion, validate identity and API contracts, model actual relationships, and review proposed repairs. Then freeze the package and compare initial versus feedback-refined construction on preregistered disjoint tasks, with the same model, actor, context entitlement, capabilities and independent grader. The independent variable is the whole construction policy, not ontology alone. Count every failure, exclusion and inconclusive cell. Host load, execution order, cold starts, missing cells, grader behavior and instrumentation overhead remain threats until that experiment measures them.
