## Contract before effects

The model must retrieve native public API evidence: a note, current date, complete phone-contact and Venmo-user identity searches, and received transactions covering the whole event day through an empty pagination page. Shares must cite distinct complete currency rows in the selected note. Supported note-row coverage is validated; unsupported formats fail closed. No amounts, people or expected recipient IDs are supplied from prior runs or evaluator internals.

Each share email must match a unique observed phone identity and a native Venmo user. The event date must equal yesterday relative to native current-time evidence. Transaction coverage must include the whole day and received direction. Account for every received transaction from those identities whose description contains the source-linked event label. Selected transaction IDs must equal that observed eligible set; an ambiguous relevant payment blocks rather than silently disappearing. Payer, receiver, positive amount, date, unique transaction identity and event-description checks precede calculation.

The actor must call host-bound `ontology.onto_reconcile`, `ontology.onto_outstanding_shares`, and `ontology.onto_request_plan` in order. These execute the frozen, live-model-generated pure functions with evidence-derived inputs. Each returns a server-owned receipt. Independent arithmetic/postcondition checks reject incorrect outputs without replacing them. The commit capability accepts only an exact, fresh plan receipt. Raw payment API calls, changed arguments, duplicate commits and premature successful task completion are denied. Auth calls remain permitted; unrelated writes are denied. This is enforcement within the supported native interface and restricted code surface, not a claim of adversarial Python sandbox security.
